# M1: Better Auth storage compatibility evidence (OQ-039)

OQ-039 is resolved **compatible for the restricted email-OTP/session subset**, using Better Auth 1.7.16 and real PostgreSQL 16.15. No Fastify server, network-facing routes, production migrations, or Railway changes are included. Existing pending auth-decision docs were preserved on branch `m1/auth-storage-compatibility`, based on `main` (`b916562`). ADR-010's library selection is accepted by the founder.

## Supported boundary

`packages/auth/src/postgres-adapter.ts` exports a Better Auth adapter factory. Its caller must provide a Postgres pool, independent 32-byte pepper/lookup keys, an AES-256-GCM keyring/current key ID, and a required audit sink. The sink receives the **same transaction client** and only model/operation/entity-ID metadata; its exception rolls back the associated mutation. The canonical audit action mapping/hash-chain writer remains a separate foundation component, not a no-op default.

Configure only the email-OTP plugin with six digits, 600-second expiry, five attempts, and `storeOTP: { hash: async otp => credentials(keys).otpHash(otp) }`. Sessions use `expiresIn: 30 * 86400`, `disableSessionRefresh: true`, and disabled cookie caching. The factory rejects password/OAuth/additional plugins, secondary storage, cached sessions, and automatic refresh. The adapter itself limits challenge expiry to ten minutes and session absolute lifetime to thirty days.

The supported user lifecycle creates users only after OTP proof (`emailVerified: true`); unverified creation is rejected. Better Auth's logical emailVerified field is a compatibility view, not a persisted authorisation claim. Only OTP sign-in is supported: it checks the code before looking up an existing user. No policy may treat the compatibility boolean as consent, membership, admin MFA, or authority.

| Hardened requirement | Implementation / executed evidence |
|---|---|
| No raw session credential in DB | Adapter generates 32 random bytes; only SHA-256(token ∥ pepper) is inserted. Tests compare the stored digest and validate rotation. |
| No plaintext email in DB | AES-256-GCM with authenticated key ID/context; keyring rotation/tamper tests; user create/read/update round trips. |
| Indexed identity lookup, no decrypt-and-scan | Email lookup is HMAC equality against the unique index. Tests capture the adapter's actual query/parameters and EXPLAIN its indexable plan. The small-fixture plan test disables sequential planning only on its dedicated test connection, then resets it. |
| Structured challenges | Hash bytes, integer attempts, expiry, and consumed timestamps map to DATA_MODEL §3 columns; no generic verification table. |
| Single consumption across processes | Atomic guarded UPDATE by a unique challenge ID, inside a transaction; two independent Better Auth instances race on one OTP, exactly one succeeds. Broad consume predicates reject without mutation. |
| Five attempts / fixed expiry | Wrong-guess restorations preserve the same row/expiry and increment its budget. A sixth attempt, even with the correct code, rejects, including when the plugin is misconfigured for 100 attempts; a one-hour plugin expiry is clamped to ten minutes. Expired OTPs never create users/sessions. |
| No stale-code resurrection | Per-email Postgres advisory transaction lock plus a latest-generation guard, including consumed rows. Failed restorations never insert new rows; duplicate unexpired code hashes reject issuance rather than make restore identity ambiguous. A deterministic delayed-guess/resend/newer-success test rejects the old OTP. Issuance timestamps advance monotonically per email under that lock, using DB time. |
| Session lifecycle | DB-time absolute and seven-day idle guards; touches at most once per five minutes; ID revocation and Better Auth revoke-all immediately invalidate lookup. UUIDv7 IDs are generated by the adapter. |
| Content-free errors / atomic audit handoff | Invalid names/keys are rejected, persistence errors are sanitised, a captured-logger sentinel test checks for leakage, and audit failure leaves no inserted user. |

## Explicit limits

- No general-purpose Better Auth adapter claim: unsupported predicates/models/operations fail closed. Tokenless stock session listing/revoke-other APIs are unsupported because stored hashes cannot reconstruct credentials. The specified future session-ID API must use safe metadata/revocation operations, not fabricate bearer tokens from hashes.
- Keep the stock Better Auth HTTP handler **unmounted**: its OTP sign-in returns a token in JSON. The future bespoke API must whitelist responses and set HttpOnly/Secure/SameSite cookies, CSRF, uniform enumeration-resistant responses, rate limits, and admin MFA. These HTTP guarantees are not established by storage tests.
- Duplicate unexpired OTP hashes fail closed; the later API can retry generation instead of reissuing an ambiguous credential. Expiry matching accounts for JavaScript Date millisecond precision without changing the stored expiry.
- Sign-in links, email changes requiring proof, account closure, and other plugins need separate integration; they are not silently mapped onto generic verification rows. No original security/schema requirement is relaxed.
- Raw IP/full user-agent values are not persisted. `created_ip_hash`, `link_token_hash`, and coarse user-agent fields remain nullable; request-aware rate limiting/IP hashing and link flow belong to later integration.
- SQL under `packages/auth/test/schema.sql` is a disposable fixture matching the relevant columns, not a migration or complete database-constraint implementation.

## Reproduce / validation

`pnpm test:auth-storage` runs ten Node tests. Point `POSTGRES_TEST_BIN` at an isolated PostgreSQL 16+ `bin` directory to create/stop a disposable Unix-socket cluster, or set `POSTGRES_TEST_URL` to an **empty loopback-only database named `echoes_auth_test` (or prefixed `echoes_auth_test_`) only**. No real content/provider keys are used. CI supplies a loopback-only disposable PostgreSQL 16 service and runs the same command; hosted results require a later authorised push.

Also run `pnpm typecheck`, `pnpm lint`, `pnpm test`, frozen install, and Gitleaks. Two separate read-only Codex reviewer sub-agents (`auth_boundary_review`, `auth_security_review`, via `collaboration.spawn_agent`) identified draft races/retention/validation issues; fixes have regression coverage. This is automated review, not human approval.

No package-manager security settings were weakened.

The final pin is 1.7.16 (published 2026-11-03T21:23:56Z), which includes the [vendor's OTP security fix](https://github.com/better-auth/better-auth/security/advisories/GHSA-2f9c-7xj7-gh55). Its OTP source is unchanged in 1.7.17; the later internal-session changes affect disabled secondary storage. The complete suite is rerun on the final pin; no release-age exception is retained.
